### 睡眠规律性

- 睡眠中点（入睡与醒来的中点）的标准差是 **15.3 分钟**（61 夜），属于「规律」。

### 指标之间的关联

下面每一条都是**相关，不是因果**：两个指标一起变，可能是其中一个影响另一个，也可能是有第三个原因同时影响两者。证据等级为「仅报数」的条目只列数值，不做解读。

证据等级看的是**效应大小相对于该指标的测量噪声**，不是相关系数。所以会出现「相关系数很高、等级却不高」的情况——那表示关系很一致，但幅度还不到这台设备的重复测量误差量级，不足以指导决定。

- **睡眠时长 → 次日静息心率**（证据中等，n=60，秩相关 -0.98）
    - 比较方式：当天与 **1 天后**配对。

    - **高**：静息心率 中位 **53**，n=29（该组睡眠/活动中位 7.67）
    - 组间差异 -3，该指标的测量噪声是 2（约 1.5 倍）。

    - **非训练日**：静息心率 中位 **54**，n=36

### 跨设备可比性

以下指标的时间线里存在**设备接替**（Apple 不标注这件事）。不同设备甚至同一设备换算法版本后，对同一个生理量的基线读数并不相同，所以曲线在换设备处的台阶很可能是**测量变了**而不是身体变了。读这些趋势时，只在同一台设备的时段内比较：
- **体脂率**：2026-05-01 前后从「InBody270」换到「智能秤」

## 附录 A：方法与口径

- **单位归一**：所有单位在解析阶段就已经归一（kg / cm / % / 次每分 / ms / km / kcal / 小时 / 级 / Ω），报告里不会再出现磅、斤、英尺混用的问题。
- **参考区间优先级**：被判定的那条观测自带的区间 > 同一设备最近提供的区间 > 项目内置的人群参考表 > 只做趋势、不下判定。末档是刻意保留的诚实：没有可比区间时，本报告不会硬编一个「正常」出来。
- **区间必须与读数同源**：设备自带的区间只能用于**它自己那台设备**的读数。拿 A 设备的数值去套 B 设备的区间，会得出一个看起来专业、实际无意义的「正常/异常」。所以内置人群参考表只在设备没提供区间时兜底，并会如实标注来源。
- **三种区间性质**：`range` 是正常参考区间；`goal` 是活动量目标（没达到只是没达到目标，不等于指标异常）；`screen` 是筛查阈值（越界只意味着值得进一步评估，同样不是诊断）。报告里的判定措辞严格区分这三者。
- **「哪一侧值得留意」**：有一批指标只有一侧是真正需要留意的信号，落在另一侧是常见甚至好事（静息心率偏低、去脂体重/骨骼肌量/蛋白质偏高、血氧偏高…）。这类越界会被降调成「通常不视为异常」，并在第一节说明原因，不列入需要留意清单。这一判断**按指标给出，不随区间边界变化**——即使区间是设备印的也一样，因为「肌肉量大的人高于一般人群的上限算不算异常」是关于指标本身的问题。
- **变化量的噪声阈值**：每个指标在 catalog 里都带一个 `noise` 值，变化量小于该值时视为测量噪声，表格里会标「噪声内」，不做解读。
- **汇总类指标**：`sum`（按日累加）与 `mean`（按日平均）类指标看变化时给的是日均值，不是首末两点之差——首末差在日间波动大的指标上会严重失真。判定也用日均值：最后一天常常只是导出当天的部分数据，拿它去比每日目标会误判。有数据日的均值与覆盖率会一起显示。
- **同一指标来自多台设备（Apple 导出常见）**：按日累加的指标（步数、距离、爬楼、能量）会按「主设备优先」取值，解析器会说明各口径下的总量差异；不做这件事的话，两台设备同时记录会被叠加。用 `--source-policy` 切换口径，用 `--prefer-source` 指定主设备。快照类指标（体重、体脂率）的多来源是**分歧**而不是口径问题，因此不做判定。
- **可比性**：同一指标出现多个来源时，来源列会标 ⚠️，**该指标不做判定**（判定列写「来源不一致，不做判定」），而且结论一节不会列出它的首末差值——跨设备的读数差不能直接当作真实变化。要看趋势请固定用同一台设备。
- **本报告不构成医学诊断**：本报告由程序根据你导入的数据自动生成，用于整理数值与趋势，它不是医学诊断，也不能替代医生、体检报告或任何专业医疗判断。报告里的参考区间来自设备说明书或公开的人群参考数据，只用来提示数值所处的位置；任何一项读数都可能受测量条件、设备型号、水合状态等因素影响，跨设备的差值不能直接当作真实变化。如果某项数值持续偏离参考区间，或你同时有不适症状，请带着原始数据咨询医生。
