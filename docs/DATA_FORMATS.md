# 输入格式

解析器接受三类输入，自动识别，可以混着给（`health-report report a.csv b.xml`），
结果会被合并成一份分析。

```
health-report report <任意数量的输入> -o 报告.md
```

识别逻辑在 `src/health_report/parsers/__init__.py` 的 `detect_kind()`。

---

## 1. Apple 健康导出

**怎么拿到**：iPhone → 健康 App → 右上角头像 → 滑到底 → 「导出所有健康数据」。
得到一个 `导出.zip`（约几十到几百 MB，取决于记录年限）。

**接受的形式**：

| 形式 | 说明 |
|---|---|
| `export.zip` / `导出.zip` | 推荐。会自动在压缩包里找 `export.xml` |
| `export.xml` / `导出.xml` | 已解压的单文件 |
| `apple_health_export/` 目录 | 内含 `export.xml` 的目录 |

**解析方式**：流式（`iterparse` + 逐元素清理），几 GB 的文件也不会吃光内存。
装了 `lxml` 会快好几倍，**不装也能跑**（退回标准库）：

```bash
pip install "health-report[fast]"    # 可选加速
```

**会提取什么**：

- **每日指标**（按 `agg` 聚合，不是逐条扔进分析）：步数、活动/基础能量、
  锻炼分钟、站立时间、爬楼层数、步行跑步与骑行距离、静息心率、HRV(SDNN)、
  VO₂max、步行平均心率、呼吸频率、血氧、体重、BMI、体脂率、去脂体重、腰围、身高
- **睡眠**：按阶段（核心/深睡/REM/清醒/卧床）汇总时长，**归属到醒来那天**
- **训练**：每次训练的时长、距离、配速、平均/最大心率、热量、运动类型（中文化）
- **个人信息**：从 `<Me>` 元素取出生日期与性别，据此推算年龄

**已知限制**：

- Apple 的日期带时区偏移（`+0800`）。解析时**丢掉偏移、只取本地时间**——
  因为导出的是本地时间，跨时区旅行的那几天归属可能差一天。
- 第三方 App 写入的指标类型五花八门。不认识的类型会被收集起来，
  在报告的「解析提示」里列出来（最多 20 个），方便你判断要不要补映射。
- `Correlation` / `ActivitySummary` 元素目前不解析（v0.1 的范围）。

## 2. InBody / 体成分仪报告（长格式 CSV）

体成分仪没有统一的机器可读导出格式，最常见的是**从报告上抄下来的长格式表**——
第一列是项目名，后面每个日期一列：

```csv
分类,指标,单位,2026-01-10 07:30,2026-05-20 07:30,变化量,报告参考范围,备注
人体成分,体重,kg,74.0,71.2,-2.8,57.0~76.0,—
人体成分,骨骼肌,kg,32.5,33.1,+0.6,—,不降反升
研究项目,身体总水分,L,42.5,44.0,+1.5,35.5~43.4,两次均高于上限
肥胖评估,身体质量指数BMI,kg/m2,25.0,24.1,-0.9,18.5~23.0,—
肥胖评估,BMI判定,—,超重,正常,—,—,—
```

**规则**：

- **日期列数量不限**（1~5 次测量都行）。表头能被解析成日期的列就是测量列；
  `分类`/`指标`/`单位`/`变化量`/`报告参考范围`/`备注` 会被跳过。
- 支持的日期写法：`2026-01-10 07:30`、`2026-01-10 07:30:00`、`2026-01-10`、`2026/01/10`。
- **指标名做模糊匹配**：`体重`、`体脂肪`、`骨骼肌指数SMI`、`右上肢20kHz`…
  都能映射到统一指标 ID（长别名优先，所以 `目标体重` 不会被 `体重` 吃掉）。
  用 `health-report metrics` 查完整的别名表。
- **`报告参考范围` 会被解析成该指标的参考区间**，优先级**高于**内置人群参考表。
  支持 `35.5~43.4`、`0.80~0.90`、`<10`、`>7`、多区间（取第一个并提示）、`—`（无区间）。
- **文字判定行**：指标名以「判定」结尾的（如 `BMI判定`）不会变成数值指标，
  而是存成设备的文字判定，供 `LABEL_CONFLICT` 规则与数值判定对比。
- **特殊行**：`身高` 同时进 profile 和指标；`年龄`、`性别` 只进 profile。
- `备注` 列的内容会作为解析提示保留（最多 30 条）。
- 单位列是 `—` 或换算不了时，按**原值**采用（体成分仪的输出口径通常已与规范单位一致），
  并在提示里说明。

**已知限制**：

- 节段百分比如果只写在 `备注` 列里（`108.0%→92.0%` 这种），v0.1 **不会**解析出来——
  解析自由文本太脆。如果设备把它作为**独立的行**给出（很多导出是这样），
  就能正常读到，`PCT_BASELINE_*` 规则也会生效。
- 从**报告照片**录入需要人工誊抄或 OCR。图片输入不在 v0.1 范围内。

## 3. 通用长格式 CSV（任何设备的万能入口）

任何设备、任何手抄数据都能用这四列进来：

```csv
date,metric,value,unit,source
2026-05-01,body_mass,74.0,kg,智能秤
2026-05-01,体脂率,21.8,%,智能秤
2026-05-01,静息心率,55,次/分,Apple Watch
2026-05-02,体重,73.7,kg,智能秤
```

**表头别名**（大小写不敏感）：

| 列 | 接受的写法 |
|---|---|
| 日期 | `date`、`日期`、`时间`、`time`、`timestamp` |
| 指标 | `metric`、`指标`、`metric_id`、`item`、`项目` |
| 数值 | `value`、`数值`、`值`、`result` |
| 单位 | `unit`、`单位` |
| 来源 | `source`、`来源`、`device`、`设备` |

- `metric` 可以是中文名（`体重`、`体脂率`）或英文 ID（`body_mass`、`body_fat_pct`）。
- 日期宽松解析：`YYYY-MM-DD`、`YYYY/MM/DD`、`YYYY-MM-DD HH:MM:SS`、`YYYY年M月D日`。
- 单位会换算到规范单位（磅→kg、米→cm、英里→km、千焦→kcal、分钟→小时…）。
  换算不了就按原值采用并提示。
- 分号、制表符分隔也能识别（自动探测）。

---

## 单位归一的约定

解析阶段就把单位统一掉，下游永远不会遇到"有的用磅有的用公斤"：

| 维度 | 规范单位 |
|---|---|
| 质量 | `kg` |
| 长度 | `cm` |
| 距离 | `km` |
| 能量 | `kcal` |
| 心率 | `次/分` |
| 血氧 / 体脂率 | `%` |
| 睡眠时长 | `小时` |
| 时长（训练） | `分钟` |
| HRV | `ms` |
| 阻抗 | `Ω` |

换算表在 `src/health_report/units.py`。查不到的换算**返回 `None`**，
由调用方决定是丢弃还是按原值保留——**不会猜**。

## 想要新的输入格式？

只需写一个函数把文件变成 `Dataset`：

```python
def parse_华为运动健康(path: str) -> Dataset:
    ds = Dataset()
    for row in 读文件(path):
        mid = catalog.resolve(row["项目"])
        if not mid:
            ds.add_note(f"不认识的指标：{row['项目']}")
            continue
        spec = catalog.get(mid)
        value = units.convert(row["数值"], row["单位"], spec.unit)
        ds.observations.append(Observation(
            metric=mid, date=row["日期"], value=value or row["数值"],
            unit=spec.unit, source="华为运动健康",
        ))
    return ds
```

然后在 `parsers/__init__.py` 的 `detect_kind()` 里加一条识别规则。
`catalog.py` 里的别名表加上你的设备用的字段名就够了——**分析层和报告层一行都不用改**。
