# 隐私

健康数据是最敏感的个人数据之一。Apple 健康的导出包里除了体重、心率、睡眠，
还有 `workout-routes/*.gpx`——**你每次跑步的 GPS 轨迹，能定位到你家门口**。

所以这个项目的默认行为是：**什么都不发出去。**

---

## 数据流：什么时候会联网

| 操作 | 联网？ | 发出去的是什么 |
|---|---|---|
| `health-report demo` | **不** | —— |
| `health-report report 文件` | **不**\* | —— |
| `health-report report 文件 --no-llm` | **不** | —— |
| `health-report report 文件 --ai-backend none` | **不** | —— |
| `health-report parse 文件` | **不** | —— |
| `health-report metrics` / `inputs` | **不** | —— |
| `health-report report 文件 --llm` | 是（若找到后端） | 只有下面那份结构化摘要 |
| `health-report report 文件 --ai-backend dsh`（或 `claude` / `codex`） | 是 | 同上 |
| `health-report report 文件 --ai-backend http` | 是 | 同上 |

\* **这一行有个前提，值得写清楚**：`report` 会自己去探测一次，但它**只会采用不出本机
或你已经显式配置过的后端**：

- 环境变量里配了 `HEALTH_REPORT_API_KEY` → 用你配的端点（你配了它 = 你知情）
- 本机 127.0.0.1 上有模型在跑（Ollama / LM Studio / llama.cpp）→ 用它，**数据不出机器**
- **本机装了 DSH / Claude Code / Codex → 探测到，但 `auto` 不会用**（见下一节）

所以"什么都不发出去"这句承诺是由**代码的默认值**兑现的，不是靠用户去读探测顺序的文档。

想 100% 保证不联网：**加 `--no-llm`**（它在探测之前就把整条 AI 路径关掉）。

---

## 「本机装的 AI 工具」不等于「模型在本地」

这是最容易误解的一处，所以单独讲。

DSH / Claude Code / Codex 是**装在你机器上的客户端，但推理在厂商云端**。
用它们 = 把你的健康摘要发给 DeepSeek / Anthropic / OpenAI。项目的处置是：

1. **`auto` 不会自动采用它们。** 哪怕三个都装好了、也都登录了，`auto` 依然选择放弃，
   生成纯规则报告。
2. **必须显式开口**：`--llm`，或者 `--ai-backend dsh`（`claude` / `codex` 同理）。
3. **每次运行都打印数据去向**，不含糊：

   ```
   [i] 用「DSH」生成解读中……
   [i] 数据将发送至：DeepSeek
   ```

> 这条限制是实测踩出来的：早期版本让 `auto` 一路探测到底，于是在装了 DSH 的机器上，
> `health-report report 导出.xml`（**既没配 key、也没加 `--llm`**）会**静默地把摘要
> 发给 DeepSeek**。对"默认什么都不发出去"来说这是不能接受的，所以改成了显式开口。
> 回归测试在 `tests/test_llm_backends.py::TestAutoNeverLeaksData`。

### 用 CLI 工具时的额外事实

如果你显式启用了它们，还有几件事应当知道：

| 事项 | 说明 |
|---|---|
| 工作目录 | 在**系统临时目录**里新建一个空目录，**只放一份 `facts.json`**，用完即删 |
| 为什么是空目录 | 这些工具本质是**编码 agent**，会读写文件、执行命令。绝不能在你的原始数据目录里跑 |
| 提示词 | 明确要求"只读这一个文件、不要执行命令、只输出正文" |
| 超时 | 默认 180 秒，不重试（它们冷启动就要十几秒）。失败静默降级，不阻塞报告 |
| 它可能写文件 | 实测 DSH 会把正文写成 `.md` 文件、stdout 只剩一句过程叙述，所以会去收集它自己写的文本文件 |
| 它可能反过来索要数据 | 若它输出「请把 facts 贴给我」，这段文字会被**判定为失败**、绝不进报告 |
| DSH 的副作用 | 第一次调用会在 `$DSH_HOME/profiles/` 下物化一个 headless profile（它自己的运行时目录） |

## 发给模型的是什么

只有 `build_facts()` 的输出。它是**已经算好的结构化摘要**，不是原始数据。
用 `--json facts.json` 可以把它原样存下来看——**在发出去之前先自己过一遍**，
这是这个 flag 存在的主要目的。

包含：

- 你的身高/年龄/性别（换算参考区间要用）
- 每个指标的：最新值、首次值、变化量、均值、数据点数、覆盖天数、**覆盖率**、参考区间文字、判定
- 命中的规则及其文字说明
- 训练汇总（次数、总时长、总距离、总热量、平均心率）
- 睡眠规律性（睡眠中点标准差、入睡/醒来中位时刻）与指标关联（含证据等级）
- 数据规模（原始记录条数、观测条数）
- 数据来源的**设备名**（已脱敏，见下）

**不包含**：

- 原始逐条记录（几千条心率、每一夜的睡眠分段）
- GPS 轨迹、运动路线
- 时间戳级别的细节（只有日期）
- 文件名与路径（`files` 字段只留 basename，且你可以用 `--json` 检查）
- 任何设备标识符、序列号、账号信息

`build_facts` 的实现在 `src/health_report/report.py`，测试里有断言
确认它不会把 `dataset.observations` 原样塞进去。**你可以自己读代码核对**，
这也是它被设计成一个独立函数的原因。

## 报告里的人名会被隐去

Apple 的默认设备名带机主姓名（「某某的 Apple Watch」）。来源名会被打印进报告，
而报告天然是要分享的——所以默认隐去姓名部分，保留器械名（你需要靠它分辨设备）：

```
某某的Apple Watch   ->   Apple Watch
```

要完全不脱敏（仅本地调试）：`--show-source-names`。

## 你连的是谁（用 HTTP 端点时）

端点完全由你决定，项目不预设任何服务商：

```bash
export HEALTH_REPORT_API_KEY="你的key"
export HEALTH_REPORT_BASE_URL="https://api.deepseek.com"     # 或任何 OpenAI 兼容端点
export HEALTH_REPORT_MODEL="deepseek-chat"
```

- 默认 base_url 是 `https://api.openai.com/v1`，仅此而已——**没有任何中间服务器**。
  不存在"作者的代理端点"这种东西。
- 请求直接由你的机器发往你配置的地址，和这个仓库的维护者无关。
- 密钥只从环境变量读，**不写配置文件、不落盘、不打印**。
  `LLMConfig.describe()` 输出配置时会把它遮蔽成 `sk-a***`，日志里也不会出现。

⚠️ **提醒**：你选择的服务商能看到你发过去的内容。如果你把 `HEALTH_REPORT_BASE_URL`
指向某个第三方代理，就等于把这份摘要交给了它。选你自己信任的端点。

## 编造的数字进不了报告

接任何模型都有一个风险：它自己编一个数值。所以 AI 写的每个数字都会**逐个回查**
那份摘要——找不到来源，含那个数字的**整句会被删掉**，报告里说明删了几处。
删完剩下的太单薄就整段丢弃、改用规则层原文。

这条是**正确性**要求，但顺带也有隐私含义：**你不需要担心模型把摘要里的数字
"改写"成别的**——改写后的数字进不了报告。

## 这个仓库里不会出现你的数据

`.gitignore` 是默认拒绝的：`*.zip`、`export.xml`、`*.gpx`、`workout-routes/`、
`InBody*.csv`、`InBody*.png` 全部被挡住，只放行 `examples/` 下的**合成**文件。

CI 里有一个 `隐私守卫` job，每次 push/PR 都会检查 `git ls-files` 里有没有
匹配这些模式的文件，命中就**直接让 CI 红**。这是为了防止"以为被忽略了、
其实早就 `git add -f` 过了"这种事。

另外：`tools/` 下如果你放了自己的验证脚本，**发布前请检查里面有没有真实数值**。
本仓库作者的自测脚本在提交前会做同样的检查——而且这一步**抓到过真问题**：
首次提交自查时发现真实姓名出现在 16 处源码里（脱敏函数的 docstring 示例、
测试夹具、断言文字）。检查方法见 `docs/RELEASE_CHECKLIST.md` 第 2 条。

## 发 issue / PR 时

- **不要**贴原始报告照片、`export.xml` 片段或任何带个人信息的截图。
- 需要举例时，用 `health-report sample-data` 生成的合成文件，或者手动改写数值。
- 症状描述足够了："同一指标两个来源，同一天差 2.4 kg，规则没触发"——
  这种描述不需要任何真实数据。

## 威胁模型：这个项目**不**防什么

诚实列出来，避免误以为是安全工具：

| 不防 | 说明 |
|---|---|
| 本机被入侵 | 数据就在你的磁盘上，明文。磁盘加密是你的操作系统的事。 |
| 你自己误提交 | `.gitignore` 和 CI 能挡住常见模式，但挡不住你 `git add -f` 之后故意推。**推送前请 `git status` 看一眼。** |
| 你显式启用的 AI 后端 | `--llm` / `--ai-backend dsh` 之后，数据一旦发出去，就受对方条款约束。 |
| 本机模型自己偷偷联网 | 探测只连 `127.0.0.1`，但**那个模型程序本身**会不会上报，是本项目管不了的。用一个你信任的。 |
| 共享电脑上的其它用户 | 产物文件（`out/*.md`、`health_out/*.csv`）是明文。 |
| 长期归档 | Apple 的导出包会越来越大、越来越敏感。定期清理旧的导出。 |

## 一句话

**默认不发；要发只发算好的摘要；发给谁由你定；发了什么你可以先看。**
